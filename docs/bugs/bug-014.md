# Bug 14 — Геймпад: hot-plug, раскладка, камера и UI

**Приоритет:** P0. **Статус:** частично исправлено 2026-10-01; активный остаток — физический hot-plug и приёмка игрового ввода/Nano на сервере.

## Объём и свидетельства

Свежие [T114–T116, T118–T120, T122](source-list-2026-10-02.md) уточняют активный остаток: Start не закрывает Enter; B вызывает Quit из других меню; D-pad/левый стик не обходят инвентарь, Nano и выбор наставника; A не спрыгивает с зиплайна; у обезьян нет выбора turbo; геймпад не подключается после старта. Проверить каждый конкретный экран и физический hot-plug, сохранив прежние бинды.

- [T069](source-list.md#t069) — Игра вылетает при подключении/отключении геймпада.
- [T070](source-list.md#t070) — Настройка инвертирования камеры по оси Y для геймпада.
- [T071](source-list.md#t071) — Должно быть по умолчанию: RT cтреляет, LT -  способность нано, D-pad вниз - Камера назад, D-pad вверх - камера вблизь, D-pad влево - журнал, D-pad вправо - поменять оружие, LB - Свободная камера (как при CTRL), RB - нано-бусты, X - Нано 1 (работает, но отзывается с задержкой), Y - Нано 2 (работает, но отзывается с задержкой), B - Нано 3 (работает, но отзывается с задержкой)/Закрыть меню интерфейса/предмета, A - Прыжок/Взаимодействие с НПС/Подтвердить в меню, выбрать предмет, L3 - Прыгнуть на транспорт, R3 - Автобег, Start - меню Enter открыть/закрыть, Back - Инвентарь
- [T072](source-list.md#t072) — Слишком чувствительная камера на геймпаде
- [T073](source-list.md#t073) — Добавить возможность переключаться по активным кнопкам в меню интерфейса при помощи D-pada

Базовый опрос и Pad-маршруты уже реализованы 2026-09-27. Новая карточка закрывает конкретные пробелы, не начинает ввод с нуля.

## Задание агенту

Сначала устранить вылет подключения/отключения. Настроить ровно указанную пользователем раскладку, контекстные A/B, задержки Nano X/Y/B, отдельную инверсию Y и чувствительность камеры. D-pad должен переводить фокус между активными кнопками открытого окна. Сохранённые пользовательские бинды не перезаписывать.

## Критерий готовности и проверка

С физическим геймпадом несколько подключений/отключений безопасны; все действия таблицы исполняются, Nano переключаются без лишней задержки, инверсия/чувствительность сохраняются, UI допускает выбор/подтверждение/закрытие.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

### 2026-10-01

Физический геймпад не обнаружен. Пользователь подтвердил: «Сейчас геймпад недоступен». Пользовательский вылет и задержка серверного переключения Nano не воспроизведены; найденные аварийные пути не объявляются доказанной причиной конкретного вылета.

В Windows WGI backend `gilrs-core 0.6.8` обнаружены `unwrap` при чтении отключаемого устройства и `expect` отправки позднего callback в уже закрытый канал. Ошибка чтения теперь пропускает опрос, ошибка перечисления кнопок/осей передаётся вызывающему коду, закрытый канал не вызывает panic. В `bevy_gilrs 0.19.1` поздние события кнопки/оси/disconnect без mapping игнорируются. Оба небольших upstream crate закреплены локальными patches в Cargo; версии остальных зависимостей сохранены. Владельцы: `vendor/gilrs-core`, `vendor/bevy_gilrs`, Cargo.toml/Cargo.lock; происхождение указано в PATCHES.md.

Раскладка Default Key Mapping соответствует T071, включая независимые LT/RT и L3/R3. Старые индексы декодируются и сохранённые пользовательские бинды не перезаписываются. A направляется на доступный NPC/trigger, иначе на прыжок; в UI A подтверждает, B закрывает через существующий Escape. Start использует тот же NanoCom reducer, что Enter. UI потребляет игровые действия, сохраняя историю удержания: закрытие окна не запускает Nano3 и не повторяет Start. Nano X/Y/B создают edge в первом кадре нажатия; серверный результат остаётся авторитетным. Причина пользовательской задержки ответа не установлена.

В Controls добавлены отдельные PAD INVERT Y-AXIS / PAD SENSITIVITY, EN/RU, Apply/Cancel и сохранение. Камера использует pad sensitivity, независимо от mouse settings; базовая скорость снижена до yaw 90°/s, pitch 60°/s. D-pad выбирает активные видимые кнопки переднего окна по геометрии и повторяет шаг при удержании. Владельцы: app/gamepad.rs, gamepad_ui.rs, hotkeys.rs, gameplay/movement, ui/option, ui/gameplay/chat_input.rs, gameplay/user_settings, localization; контракт обновлён в docs/ui/options.md.

### 2026-10-03

Новая таблица T114–T122: Start теперь проходит к общему Enter/NanoCom reducer и при открытом NanoCom; этот экран блокирует движение, но не повторное нажатие Start. B продолжает передавать Escape владельцу открытого окна, а Quit игнорирует синтетический Escape этого же кадра, поэтому закрытие другого меню не открывает Quit. Левый стик подаёт направления фокуса с мёртвой зоной 0,55, D-pad имеет приоритет по каждой оси. На зиплайне A направляется в прыжок, даже если поблизости остаётся NPC/trigger. Общий UI-фокус охватывает видимые `Button` инвентаря/Nano, выбора наставника и транспорта, включая Turbo у Wyvern; отдельного обхода этих экранов не добавлено.

В WGI backend добавлена сверка списка контроллеров с предыдущим опросом для подключения во время игры при пропущенном системном callback. Сверка сохраняет ID отключённого устройства, обновляет WinRT handle при повторном подключении того же контроллера, игнорирует повторные callback/опрос события и пропускает неполное перечисление. Это исправление пути T122 на уровне кода, но физический USB/Bluetooth hot-plug остаётся неподтверждённым.

### Дополнение пользователя 2026-10-03: удержание, фокус и отдельные экраны

Новый объём: голубой фокус предметов/Nano/журнала/магазинов/транспорта и крестиков; повторный A после смены состояния кнопки; удержание A на стрелках; выбор персонажа; первая опция NPC; B закрывает карточку предмета; LB/RB переключают вкладки инвентаря, почты и журнала; A пропускает катсцены и заряжает пушку. Пользователь уточнил: вкладки чата геймпадом переключать не нужно. Физического устройства сейчас нет.

Причины и изменения:

- `Interaction` геймпада отделён от сброса мышиного hit-test: сохраняются удержание, отпускание и отдельный новый press. Стрелки создания персонажа получают повтор через 0,35 с, затем каждые 0,12 с; непрерывные контролы читают удержанный `Pressed`. Голубая рамка с полупрозрачной заливкой рисуется поверх дочерних иконок и переносится вместе с фокусом.
- Раздельные слои отрисовки выбора персонажа объединены в одну область навигации; модальные окна остаются отдельными. В NPC начальный фокус получают строки действий/миссий. Карточки предметов, Nano и справка инвентаря удерживают фокус внутри себя.
- Для предметов A открывает карточку напрямую: прежний обработчик ожидал физическое начало/завершение mouse drag. B проходит существующий Escape, закрывающий сначала карточку. Вкладки инвентаря, почты и журнала размечены для LB/RB.
- Tutorial учитывается как игровое состояние; HUD больше не перехватывает его движение. Вкладки чата исключены из pad-кандидатов. Катсцены принимают A, туториальный Nano — X. Пушка получает оси и press/release геймпада; потеря устройства отменяет заряд без выстрела и сбрасывает автобег.
- WGI передаёт полный начальный снимок осей/кнопок, очищает показания отключённых устройств и продолжает очередь после дублей callback. Раннее событие ввода больше не создаёт скрытое подключение, из-за которого последующий Connected подавлялся и Bevy не получал устройство.
