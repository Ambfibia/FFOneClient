## Задание агенту

Остаток: проверить группы 0 и 27 в реальном клиенте с RustyFusion и повторный бой после возврата у патрулирующего моба. При отсутствии группы записать место, канал/instance, входящие NPC_ENTER и ID исчезнувших участников; серверные данные и отправка состава уже проверены, повторно менять их без нового свидетельства не нужно.

## Критерий готовности и проверка

Моб после возврата допускает новый нормальный бой; принятые группы появляются в своих местах и не распадаются из-за reset.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01:

- **T038 — code-fixed.** Регрессия с NPC type 59 / runtime ID 2000000920: первый возврат после выхода за 4000 единиц; затем позиция нового боя на 9000 единиц дальше первоначального спавна; три новых удара. При прежнем `check_retreat` первый новый удар вызывает очередной reset (`new hit triggered another reset`). Исправленный вариант допускает бой, а последующий выход игрока за дальность нового боя вызывает один нормальный возврат с лечением.
- Причина: RustyFusion считал leash от постоянного `spawn_position`. У патрулей/следующих за лидером мобов новый бой вдали от спавна немедленно нарушал этот предел. В локальном OpenFusion `MobAI::onCombatStart` сохраняет `roamX/Y/Z`, и `combatStep`/`retreatStep` используют эту позицию текущего боя.
- Исправление в `../RustyFusion`: `src/entity/npc.rs` сохраняет `combat_origin` при первом захвате цели через `acquire_target` и очищает его при reset; получение урона и скриптовый `set_target` используют один путь. `src/scripting/npc.rs` предоставляет эту позицию AI; `scripts/lib/behaviors.luau` использует её для leash и возврата. Повторный урон не сдвигает центр текущего боя. Wire IDs и размещения не менялись.
- **T040 — серверная часть проверена, живой остаток активен.** В `tabledata/mobs.json` есть 364 группы из трёх участников и 6 групп с четырьмя спутниками; SHA256 совпадает с `../OpenFusion/tdata/mobs.json`: `FCC99C097B2235152C217C27F0BE8C4273F8DAD1DDE9F4E3D8B84E08238B7F37`. Новый тест подтверждает создание всех NPC, типы/координаты, `tight_follow`, выбор AI и 3/5 пакетов NPC_ENTER наблюдателю. Данные групп уже поддерживаются существующим `make_group_npcs`; причина жалобы на отсутствие в игре не доказана.
- Тройка **group 0**, leader/followers type **174**: `(536307, 457315, -4435)`, map 0, channel 1. Босс **group 27**, type **521**, четыре спутника type **133**: `(497662, 513961, -5096)`, map 0, channel 1. Все координаты серверные 0104.
- Добавлены две регрессии в `src/ai_tests.rs`. Адресный набор `ai::tests`: **12 passed**. Проверены повторный бой, лечение для старого/нового наблюдателя, следование и сброс спутника, патрульные маршруты, составы групп и NPC_ENTER.
- Независимая сборка этой копии в `target/bug042-build` также прошла: **12 AI + 9 damage + 12 crowd-control + 15 corruption = 48 passed**. Проверки damage/CC/corruption расширены из-за изменения общего пути захвата цели при уроне. Логи: `target/bug042-ai-independent.log` и `target/bug042-verify-6986018b/{damage,cc,corruption}-final.log`. `git diff --check` затронутых серверных файлов passed.
- Сборка рабочего дерева временно блокировалась параллельными незавершёнными изменениями обмена/escort. Проверка выполнена в копии `../RustyFusion/target/bug042-verify-6986018b` с теми же затронутыми файлами и данными; только незавершённая посторонняя проверка `m_iCSUDEPNPCFollow` отключена в копии, исходник не менялся. Первоначальная проверка позиции после пяти секунд мирного roaming была исправлена на координаты ReturnHomeHeal. Один первый прогон существующего теста следования завершился ошибкой дистанции; отдельный и последующий полный адресный прогон прошли.
- **Ограничение:** это серверные сценарии с настоящими AI/Luau, tick, таблицами и очередью пакетов; игровой проход в реальном клиенте не выполнен. Bug 42 остаётся в активной очереди с указанным узким остатком; полная приёмка не заявляется.
