# Bug 75 — Эффект телепортации машины времени

## Задание

Найти событие входа/выхода машины времени и существующий native эффект; проверить время запуска относительно перехода локации.

## Область и проверка

Машина времени; [native asset workflow](../../../native-asset-workflow.md). Эффект виден при телепортации без преждевременного скрытия загрузкой.

## Результат

Сценарий T153: оплативший игрок после восстановления машины времени выбирает первого гида у NPC типа 1425; успешная смена гида запускает warp ID 76 в прошлое (TableData, цель map 0, 373330/442600/-5700). При чтении кодового пути установлено: `GuideUiAction::FirstMentorChangeSucceeded` создавал `PendingGuideWarp`, затем через 1,5 секунды посылал `UseNpcWarp`, но не ставил эффект. Это соответствует отсутствующему визуальному переходу в жалобе. Живое прохождение указанного аккаунта не выполнено.

В `app/guide.rs` на этом событии теперь ставится уже используемый native эффект ES394 у локального игрока. Запрос warp ждёт готовности и завершения экземпляра эффекта, используя тот же `WarpDepartureClock`, что обычный NPC warp. `warp_presentation.rs` удерживает состояние перехода до загрузки новой локации. Серверные данные, ID и asset не менялись.

Проверки 2026-10-03: `cargo check -p ffone-client --bin ffone-client` прошёл; `cargo test -p ffone-client --bin ffone-client time_machine_warp_waits_for_native_effect_and_keeps_transition_during_loading -- --nocapture` — 1 passed. Тест проверяет ожидание готовности и окончания ES394 до запроса warp, а также удержание перехода при загрузке назначения. `git diff --check` для изменённых Rust-файлов прошёл. Живая приёмка видимости ES394 у машины времени и успешного перехода с RustyFusion остаётся открытой; полная приёмка не заявлена.
