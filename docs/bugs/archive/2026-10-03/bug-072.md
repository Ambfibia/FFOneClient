# Bug 72 — Две реплики одновременно на финише гонки

**Приоритет:** P2. **Статус:** code-fixed 2026-10-03; живая приёмка финиша не подтверждена.

## Свидетельства

T131. Точный текст: [реестр](../../source-list-2026-10-02.md); [исходная таблица](../../evidence/2026-10-02/open-bugs-table.tsv). Координат, клипа и ID NPC в жалобе нет.

## Задание

Записать два аудиособытия и порядок финишных пакетов; исключить одновременный запуск дублирующих реплик.

## Область и проверка

Аудио гонки; docs/localization-and-voice.md. Владелец определён через [source-map](../../../source-map.md). На одном финише должна звучать одна реплика; повторный финиш должен работать.

## Результат

Статический путь события: при открытии финишного NPC категории 14 во время активной гонки `world_npc_interaction.rs` вызывал `legacy_npc_open_voice_cue(14, true, ...)`, выбирал `RaceEnd` и ставил `*_racefinished0N` в очередь `GameplayAudioRuntime`. Затем открывался `EndEcom`, отправлялся запрос завершения, а ответ `RACE_END_SUCCESS_PACKET_ID` через `apply_correlated_race_reply_0104` ставил `PendingRaceNpcVoice::RaceFinished`. `consume_race_production_outputs` запускал вторую запись того же семейства `*_RaceFinished0N`. Звук `audio/sfx/ui/racefinish.ogg` — отдельный SFX. При закрытии NPC после успешного результата прежний `finished_voice_npc_id` уже подавляет `Farewell`.

Исправление: при открытии NPC не ставить `LegacyNpcVoiceCue::RaceEnd` в очередь. Единственным владельцем финишной реплики остаётся подтверждённый `EndSuccess`. Новое открытие `RaceMode` сбрасывает `finished_voice_npc_id`, поэтому следующий забег может озвучить свой финиш. Другие приветствия NPC и финишный SFX сохранены.

Проверки: `cargo test -p ffone-client --lib race_ui::mode::tests` собрал библиотечный test binary (фильтр не совпал с именами тестов, 0 запущено). Из того же нового binary адресно выполнены и прошли `end_success_updates_result_status_and_exact_inventory_effects` и `npc_dialogue_voice_names_follow_call_voice_play_and_resolve_both_locales` (по 1 тесту). `git diff --check` для исправленного Rust-файла прошёл.

Ограничения: `cargo check -p ffone-client --bin ffone-client --locked` ожидал общий Cargo build lock, занятый параллельными сборками в этом workspace, и был остановлен до компиляции бинарника; его успешная сборка не заявляется. Реальный финиш с RustyFusion, порядок пакетов в живом соединении и повторный забег не проверены: запущенного клиента/сервера и точной локации из жалобы нет. Вывод о двух аудиособытиях и порядке сделан по исполняемым путям, а не по записанному сетевому трейсу.

**T131: code-fixed, снят из активной очереди; живая приёмка остаётся неподтверждённой.**
