## Задание агенту

Выбрать нижний правый Nano HUD, увеличить корректную область видимости/клиппинга портрета без нарушения соседних кнопок и safe area.

## Критерий готовности и проверка

Высокие Nano не обрезаются неправильно на поддерживаемых разрешениях; кнопки/счётчики доступны.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01, T033. Владелец нижнего правого HUD — `nano_wheel.rs`; `active_nano.rs` относится к отдельной верхней левой полосе. Родитель wheel уже разрешал выход детей за свои границы. Реальное ограничение задавали квадратные 72×72 UI-портреты и 144×144 render targets: часть модели выше верхней границы не попадала в изображение.

Три портрета увеличены до 72×108 (y=-24 вместо 12), targets — до 144×216. `SubCameraView` расширяет прежний квадрат только вверх на 36 logical pixels / 72 texels. Ширина, масштаб модели и нижний край y=84 сохранены. CPU frustum culling отключён только для мешей трёх HUD-риг, поскольку Bevy 0.19.1 вычисляет его без `SubCameraView`; отдельные волосы/голова в дополнительной области не должны исчезать. Journal, кнопки, stamina, affinity и счётчики сохраняют свои размеры и слои.

Изменены `ui/gameplay/nano_wheel.rs`, `characters/gameplay_nano_portraits/{mod,tests}.rs`, `ui/gameplay/tests/layout.rs` и контракт `docs/ui/nano-hud.md`. Адресный full-client fixture `FFONE_PERF_NANO_HUD=1` использует Swampfire 24, Belladonna 42 и Computress 43; `FFONE_PERF_NANO_HUD_BASELINE=1` возвращает прежний квадрат только для A/B-проверки.

Проверки: новый `target/debug/deps/ffone_client-300cdf94d89a9153.exe` от 2026-10-01 21:05:54, фильтр `characters::gameplay_nano_portraits::tests::`: **7 passed**, включая новую регрессию экранных координат, видимости над старой границей, пропорций UI/target и сохранения journal. Фильтр `ui::gameplay::tests::layout::exact_retrobution_rectangles_are_stable`: **1 passed**. Дополнительно та же новая регрессия прошла в изолированном Rust harness, извлечённом из production source с текущим Bevy; этот harness не подменяет сборку приложения.

Сборка `cargo build -p ffone-client --bin ffone-client --features diagnostics --locked`: **PASS**. Проверены отдельные копии полных бинарников от 21:16:11 и 21:22:18, чтобы параллельные сборки не меняли запущенный executable. Второй бинарник включает `FFONE_PERF_NANO_HUD_IDS` для явного выбора тройки.

Полный offline-клиент, Южный Поки-Оукс, `FFONE_PERF_NANO_HUD=1`, `FFONE_PERF_FREEZE=1`: четыре прохода (старый квадрат / исправленная область для 24,42,43 и для 6,12,35), каждый с реальным resize 1280×720 → 1024×768 → 1920×1080. **Все четыре exit 0**, всего 12 кадров; assertions размеров render targets прошли. Swampfire/Belladonna/Computress не демонстрировали заметного верхнего обрезания в этой позе. Для Aku 35 старый квадрат срезал небольшую часть верхнего контура центральных рогов; расширенная область возвращает контур без увеличения модели. Wilt 6 и Professor Utonium 12 также отображаются, skill/affinity/stamina сохраняют расположение. Шесть кадров высокой тройки сохранены в [evidence](../../evidence/2026-10-01/bug-053/).

Ограничения: на 1024×768 раскрытый чат перекрывает батарейные счётчики **в обоих** режимах A/B; это прежний отдельный layout-конфликт, расширение портретов его не добавляет. На 1280×720 и 1920×1080 счётчики видны. Проверена презентация шести Nano и трёх разрешений, не весь каталог/все позы. Offline fixture не подтверждает серверные команды выбора/навыков; сетевой код Bug 53 не меняет. FPS по параллельно нагруженной рабочей области не заявляется.
