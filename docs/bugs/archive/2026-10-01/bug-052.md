# Bug 52 — Красный фильтр недоступных предметов

**Приоритет:** P2. **Статус:** исправлено в коде 2026-10-01; отображение принято в полном клиенте с offline authority. T021 снят из активной очереди; серверный диалог смены гида не проверялся.

## Объём и свидетельства

- [T021](../../source-list.md#t021) — Недоступные предметы не имеют красного фильтра в инвентаре (например, вещи другого гида)

## Точки входа

- [crates/ffone-client/src/ui/user_equip](../../../../crates/ffone-client/src/ui/user_equip)
- Нативный владелец инвентаря подтверждён: `UserEquipUiElement::InventorySlotIcon` в [binding/slot_elements.rs](../../../../crates/ffone-client/src/ui/user_equip/binding/slot_elements.rs); [source-map](../../../source-map.md).

Сначала поиск символов, затем чтение совпавших диапазонов. Для серверного результата найти владельца в `../RustyFusion` и прочитать его AGENTS.md перед изменением. Контракты и порядок выполнения — в [AGENTS.md](../../AGENTS.md).

## Задание агенту

Найти владельца слотов инвентаря и условие доступности по гиду/ограничениям. Применить красный фильтр к недоступному предмету без изменения его исходной иконки.

## Критерий готовности и проверка

Предмет другого гида выделен красным; разрешённый предмет отображается нормально; изменение гида обновляет доступность.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01. Причина: `InventorySlotIcon` всегда получал белый цвет; единственным изменением была прозрачность источника перетаскивания. Требования `m_iMentor`, `m_iReqSex`, `m_iMinReqLev` уже загружались в native metadata, но отрисовка инвентаря их не использовала.

Добавлен read-only `gameplay_inventory_item_available`: ограничения берутся из базового wire ID, независимо от комбинированной внешности. `UserEquipPresentationContext` получает пол и raw mentor из действующих runtime owners. Binding каждого кадра применяет sRGBA `(1, .2, .2, 1)` для недоступного предмета и белый цвет для доступного; у источника drag альфа остаётся `.5`. Изменение гида или уровня обновляет фильтр без изменения слотов и повторного открытия окна. Исходные PNG, IDs, локализация и шрифты сохранены.

Изменены `ui/user_equip/{state.rs,binding/slot_elements.rs}`, `app/user_equip.rs`, метод в `tutorial_runtime/mission_content/types_tutorial_mission_content_gameplay_mission_na.rs`, регрессия в `tests/operations_real_assets_game_table_set_has_exact_tutoria.rs`; адаптирован literal контекста `examples/ui/user_equip_ui_gpu_preview/main.rs`. Сценарий полного клиента — `app/performance_probe/inventory_availability.rs`, opt-in подключение в `performance_probe.rs` и `performance_probe/output.rs`.

Проверки:

- `cargo test -p ffone-client --features diagnostics --lib inventory_ --locked`: **45 passed**, включая новую регрессию смены гида, границы уровня, пола, базовой/комбинированной идентичности и Quest fallback.
- `cargo build -p ffone-client --bin ffone-client --features diagnostics --locked`: **PASS**. После исправления проверки цветов финальный диагностический бинарник собран отдельно с параметрами rustc от Cargo и уже собранными зависимостями, exit 0; SHA256 `C414102D371DC701F737620ACDC182D06153D092795754C89E8557B3803B8485`. Отдельная проверка компиляции UserEquip GPU example с обновлённым публичным контекстом: **PASS**.
- Полный клиент DX12, 1920×1080, `FFONE_PERF_OUTPUT=target/bug052-inventory`, `FFONE_PERF_INVENTORY_AVAILABILITY=1`: **exit 0, 5/5 этапов PASS**. Инвентарь: weapon ID 2 (Ben, level 24), нейтральный ID 10 (level 23), ID 2 с внешностью ID 10. Dexter/36 → Ben/36 → Ben/23 → drag slot 0 → cancel. В каждом этапе проверены цвет и видимость всех трёх иконок и корня UI. Все пять `inventory-stage-0..4.png` визуально осмотрены: красный фильтр, его снятие, повторное ограничение по уровню и корректная альфа drag/cancel подтверждены.

Артефакты: `target/bug052-inventory`, `target/bug052-inventory-runtime.log`, `target/bug052-inventory-errors.log`. Первые два диагностических запуска остановились на сравнении разных представлений белого цвета и округлении linear→sRGB; исправлена только проверка ожидаемых значений, они не засчитывались как PASS. Основные Cargo-команды долго ожидали общую блокировку `target`; отдельные проверки использовали собственные output/incremental каталоги.

Ограничение: настоящий интерфейс и GPU, но inventory/mentor/level задавались offline authoritative fixture; ручные клики Guide Changer, серверный ответ и повторный вход не проверены. **T021 — code-fixed, отображение проверено в полном offline-клиенте.** Точные выполненные проверки сохранены в [verification](../../verification.md).
