## Задание агенту

Найти владельца парсинга и серверных ответов /help и /redeem. Исправить маршрутизацию/аргументы/локализованный ответ, сохранив допустимость redeem и защиту повторного погашения.

## Критерий готовности и проверка

/help выдаёт справку; корректный, неверный и повторный redeem получают правильные результаты без повторной выдачи награды.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01. T042 снят как **code-fixed**, Bug ID сохранён.

Установленные причины:

- RustyFusion `cmd_help` помещал 18 описаний в один `szSystemMsg[512]`: UTF-16 encoding возвращал ошибку, вместо справки уходил FreeChat FAIL. Новая регрессия подтверждает, что прежнее объединение списка не помещается в 512 единиц UTF-16.
- `/redeem` отсутствовал в реестре команд и загрузчике RustyFusion. Локальный OpenFusion использует `CodeItems` / `ItemReferenceIDs` и сохраняет погашение на персонажа; этот контракт перенесён в основной сервер.
- Серверные ответы попадают в ALL/GROUP, поэтому ввод из BUDDY оставлял их невидимыми. Отправка серверной команды из BUDDY теперь выбирает ALL.

Изменения:

- `../RustyFusion/src/server/shard/chat.rs`: справка идёт отдельными отсортированными строками; `/redeem` зарегистрирован для обычного игрока, как и `/help`.
- `../RustyFusion/src/server/shard/chat_redeem.rs`: аргументы и ASCII-регистр кода, проверка повторного погашения, всей вместимости награды и текущего обмена; предметы публикуются только после сохранения. Никакой предварительной клиентской выдачи.
- `../RustyFusion/src/tabledata.rs`: optional `CodeItems` из существующего `drops.json`, допустимы object/array; пустые награды, неизвестные ссылки, некорректные ID/типы и повторные коды отклоняются. Награды используют существующие `ItemReferences` и проверенные item stats.
- SQLite/PostgreSQL: additive `RedeemedCodes` с ключом `(PlayerID, Code)` и каскадным удалением. Claim и сохранение персонажа/инвентаря выполняются одной транзакцией. Повторный claim не перезаписывает награду даже устаревшим кандидатом.
- Клиент: `app/gameplay_ui_actions/chat.rs`, `app/social_ingress/{codec,command_text}.rs`, 29 ключей EN/RU и адресные регрессии. Локализуются только точные известные ответы, произвольный серверный текст сохраняется.
- Полный клиентский replay: `app/performance_probe/chat_commands.rs`, флаг `FFONE_PERF_CHAT_COMMANDS=1` вместе с `FFONE_PERF_OUTPUT`.

Проверки:

- RustyFusion `cargo test --lib chat_command_tests`: **6 passed**. `/help` и `!help`, обычный accountLevel 99 с FreeChat mute, отсутствие broadcast, неизвестный/пустой redeem и неверное число аргументов; существующие `/level` и `/whois` сохранены.
- `cargo test --lib redeem`: **3 passed** в окончательном запуске. Определения кодов; справка; reward fixture `test` → два General item 119, слоты 0/1. Проверены повтор, stale candidate, сохранение/повторное открытие SQLite, полный инвентарь, обмен и искусственный отказ INSERT в inventory. При отказе нет предметного пакета, изменения живого инвентаря или claim; прежняя БД остаётся целой, после удаления аварийного trigger погашение доступно.
- `cargo test --lib test_player_save_reload`: **1 passed**. Всего **9 уникальных серверных тестов**, пересечение фильтров не суммируется повторно.
- `cargo check --lib --no-default-features --features postgres` и `cargo build --bin hybrid`: успешно. PostgreSQL round trip не запускался.
- Прямой Rust harness подключает текущий production `command_text.rs` и настоящий `ffone_client::localization`: **1 passed**, все 29 новых ключей проверены по реальным EN/RU bundles.
- RU: копия свежего Cargo-исполняемого файла в `target/bug-056/client-cargo.exe`; EN: текущий production `src/main.rs` собран напрямую rustc на существующих зависимостях в изолированный `target/bug-056/ffone-client.exe`. Оба запуска с `--language ru/en`, offline authority: **exit 0**. Replay проверяет consumption ввода через production Enter reducer, BUDDY → ALL и наличие каждой строки в реально привязанных Bevy `Text`.
- Скриншоты [RU help](../../../../target/bug-056/ru/chat-25.png), [RU redeem](../../../../target/bug-056/ru/chat-65.png), [EN help](../../../../target/bug-056/en/chat-25.png), [EN redeem](../../../../target/bug-056/en/chat-65.png) и `chat-*-pass.txt` сохранены; RU/EN redeem визуально осмотрены, текст читается без обрезания.

Ограничения:

- В текущих `RustyFusion/tabledata/drops.json` и `OpenFusion/tdata/drops.json` нет `CodeItems`. Рабочие промокоды и награды не выдумывались. Сервер поддерживает утверждённые определения вида `CodeItems: [{"Code":"...","ItemReferenceIDs":[...]}]`; без них корректный ответ — неизвестный код. Тестовый `test` не добавлен в production данные.
- UI replay подаёт decoded server replies и не подключается к shard. Серверная авторитетная выдача проверена отдельно на изолированной SQLite. Полный TCP сценарий реального промокода и PostgreSQL persistence остаются неподтверждёнными.
- Адресный Cargo-тест client bin и собственная повторная Cargo-сборка были остановлены после длительного ожидания общей очереди; они не засчитываются как выполненные. Успешные native запуски и отдельный localization harness перечислены выше. Первый прямой build на старой cached library выявил несовпадение API другой текущей задачи; окончательный build использует актуальную библиотеку и завершился успешно.
