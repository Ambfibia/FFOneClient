## Задание агенту

Выбрать экран email и исправить порядок вкладки относительно рамки/содержимого, включая active/hover состояния.

## Критерий готовности и проверка

В реальном email-окне вкладка занимает свой слой при переключении и не перекрывает соседние элементы.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01. Причина T020: `spawn_email_list_panel` создавал player-tab последним,
после рамки списка и guide-tab. Все три изображения player-tab (normal, active,
hover) поэтому перекрывали верхнюю рамку и край соседней вкладки.

Порядок native sibling-элементов изменён на inactive fill → player-tab → list rim
→ guide-tab → подписи. Рамка и guide-tab закрывают нижний/левый край player-tab;
верхняя часть, подпись и Button сохраняются. Смена изображения при active/hover
не меняет порядок. Assets, geometry, локализация и сетевой протокол не изменены.

Изменены `src/ui/email/view_email_list_panel.rs`, добавлена ECS-регрессия в
`src/ui/email/tests/layout.rs` и opt-in `FFONE_PERF_EMAIL_TABS` в существующем
full-client email fixture. Контракт уточнён в `docs/ui/email.md`.

Проверки:

- Production library test-exe `ffone_client-300cdf94d89a9153.exe` от 21:05:
  `ui::email::tests::` — **33 passed**, включая новую ECS-регрессию. Те же
  текущие email-исходники отдельно собраны через существующий preview main с
  `rustc --test`; **33 passed**. Это один набор регрессий, не 66 разных тестов.
- Полное приложение, RU и EN, `FFONE_PERF_EMAIL=1`, `FFONE_PERF_EMAIL_TABS=1`:
  оба запуска **exit 0**. Шесть состояний на язык: Guide selected без hover,
  hover Player, hover Guide; Player selected без hover, hover Player, hover Guide.
  На каждом кадре runtime assertions проверили folder и фактический
  `ComputedStackIndex`: Player < list rim < Guide. Все 12 кадров осмотрены:
  рамка закрывает нижний край Player, соседняя вкладка — левый край;
  подписи видимы, переключение/hover не поднимают Player поверх рамки.
- `git diff --check` затронутых файлов passed.

Кадры и логи: [evidence/2026-10-01/bug-050](../../evidence/2026-10-01/bug-050/),
[сравнение всех состояний RU/EN](../../evidence/2026-10-01/bug-050/tabs-contact.png).

Ограничения: приёмка относится к native presentation пустого mailbox в полном
приложении, открытого production `open_email_ui`; папки переключаются production
`switch_email_folder`, hover подаётся ECS-fixture. Сценарий NanoCom/серверных писем
не принят: обычная offline-fixture сейчас останавливается на authoritative inventory.
Windows helper дважды вернул `foreground window did not report a process id`;
физический указатель не проверен. Отдельный GPU-preview остановился на несвязанной
проверке размера FROM, поэтому его результат не засчитан.

Из-за общей очереди Cargo проверочный full-client exe связан напрямую с
production library `libffone_client-f67341a256be7209.rlib` от 21:01 и точными
dependency fingerprints. Временный entry-point в `target/bug-050-client-main.rs`
реэкспортирует эту библиотеку и добавляет только отсутствовавший в ней новый
`world_pc_in_interaction_range` с текущей формулой (extent + 25 × 0.5);
email/world app и assets берутся из production владельцев. Основные исходники
этого helper не изменялись; offline-проверка почты не использует PC interaction.
Это диагностическая сборка, штатная Cargo-сборка всего текущего дерева не заявляется.

T020 снят как code-fixed с проверенной native presentation и указанными
ограничениями живого входа/физического указателя.
