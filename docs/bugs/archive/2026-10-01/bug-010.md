# Bug 10 — Барбер открывается, но возвращает unavailable

**Приоритет:** P1. **Статус:** код исправлен 2026-10-01; живая приёмка не подтверждена. Снят из активной очереди как code-fixed, без заявления о полной приёмке.

## Объём и свидетельство

- [T005](../../source-list.md#t005): меню барбера открывается, но показывает «The Barber is unavailable. Please try later».
- [Предыдущая карточка](../2026-09-27/bug-010.md): пять серверных тестов покрывали искусственный NPC типа 3470.

## Причина и исправление

`app/barber.rs::send` создаёт `RegisteredGameplayRequest0104`. Клиентский список разрешённых запросов содержал исторические регистрации OpenFusion, но не нативные обработчики RustyFusion `P_CL2FE_REQ_PC_BARBER_OPEN` (0x130000a5) и `P_CL2FE_REQ_PC_BARBER_CONFIRM` (0x130000a6). Создание запроса завершалось `UnregisteredPacket` до отправки серверу; открытие UI показывало `ui.barber.unavailable`. Ошибка общая для любого владельца барбера, независимо от type/instance.

В [registry.rs](../../../../../crates/ffone-protocol/src/registry.rs) добавлены две регистрации RustyFusion и строгие размеры тел 4/76 байт. Исторический список из 131 регистрации OpenFusion сохранён. Серверные проверки владельца, расстояния, цены и подтверждения не изменены. Регрессии добавлены в [registry/tests.rs](../../../../../crates/ffone-protocol/src/registry/tests.rs) и [net/tests/codec.rs](../../../../../crates/ffone-net/src/tests/codec.rs).

## Проверки и ограничения

- Новый протокольный тест до исправления воспроизвёл `UnregisteredPacket { packet_type: 318767269 }` для запроса открытия; после исправления проходят оба запроса, отклоняются размеры ±1 байт.
- `cargo test -p ffone-protocol --lib registry:: -- --nocapture`: 5 passed; исторические регистрации и проверки неизвестных/неверных пакетов сохранены.
- `cargo test -p ffone-client-network --lib registered -- --nocapture`: 1 passed, 33 filtered out.
- `cargo test -p ffone-net --lib gameplay_sender_barber -- --nocapture`: 1 passed, 30 filtered out. Оба запроса получены TCP-приёмником после расшифровки с последовательными checksum 0/1; совпадают ID и всё тело.
- `cargo build -p ffone-client --bin ffone-client --locked`: успешно, обновлён `target/debug/ffone-client.exe`.
- `git diff --check` по затронутым файлам: успешно.
- RustyFusion: `cargo test --locked --lib barber:: -- --test-threads=1`: 5 passed. Проверены quote/confirm, стоимость изменённых полей, повтор, observer, недопустимые значения/деньги/место/расстояние и SQLite reload внешности, денег и одежды на изолированной БД.
- В таблице RustyFusion категория 28 принадлежит типам 3470, 3477, 3480, 3483, 3486; проверка сервера использует категорию, а не один hardcoded тип. Конкретный runtime ID из пользовательского сценария неизвестен; тестовый ID — 900347, тип 3470.
- Живая приёмка не выполнена: процессы ffone-client/RustyFusion отсутствуют, локальный login 23000 не слушается, FFONE_LOGIN_ADDRESS/FFONE_USERNAME/FFONE_PASSWORD отсутствуют. Изменение внешности через настоящий UI и повторный вход остаются неподтверждёнными. GPU preview не использовался как замена серверному сценарию.
