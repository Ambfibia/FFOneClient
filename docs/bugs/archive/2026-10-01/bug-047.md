## Задание агенту

В миссии «В Вихрь» установить точный объект/NPC и проверить единый порог выбора, открытия и исполнения действия на клиенте/сервере. Не обходить серверную проверку расстояния.

## Критерий готовности и проверка

В допустимой дистанции действие миссии доступно и завершается; слишком дальний клик не оставляет открытый неработающий диалог.

Проверить только затронутый сценарий и подходящие уникальные регрессии. Для новых UI/графики/анимаций/аудио нужен реальный клиент; для обмена/удалённого аватара — два клиента и сервер. Нулевой набор тестов не подтверждает результат. Если необходимый запуск недоступен, явно оставить живую приёмку неподтверждённой.

## Результат выполнения

2026-10-01, T023 — **code-fixed**, снят из активной очереди. Полную живую приёмку не заявляем.

- Установлен конкретный сценарий по native TableData: миссия 520 «Прямо в Вихрь», задачи 598/599/600 → временные точки NPC type 1088/1089/1090 (class 100, sight range 1500, height 200); задача 601 → NPC 1130 «Вихрь времени» (sight range 700). Runtime ID в подготовленном offline replay: 1900047, type 1088, task 598. Исторический runtime ID пользователя неизвестен.
- Причина: `world_npc_target_sample` разрешал TalkNpc по расстоянию от глаз до видимой части NPC и `m_iSightRange`. На расстоянии 12 native units временная точка попадала в view/talk (1200 < 1500), открывая меню. RustyFusion `task_end` для этого типа задачи применяет `RANGE_INTERACT = 800` между позициями сущностей по трём осям и отвергает действие. Несогласованность воспроизведена на уровне targeting/action resolver; исходный игровой сеанс пользователя не воспроизводился.
- Исправление: общий `world_npc_in_interaction_range` повторяет wire truncation координат и включённую целочисленную границу серверного distance_to. Он ограничивает talk feed, повторно проверяет живые Transform перед открытием NPC и проверяет текущего NPC/игрока перед открытием страницы, TaskStart и QuestEnd. Пропавший, неоднозначный, мёртвый или дальний NPC закрывает локальный диалог и снимает pending до регистрации/отправки запроса. Sight range, view/LOS, IDs, RU/EN сохранены; сервер и награды не менялись.
- Файлы: `world_systems/targeting/{mod,tests}.rs`, `app/world_npc_interaction.rs`, `app/gameplay_ui_actions/mission.rs`. Подготовлен адресный full-client replay `app/performance_probe/npc_interaction_range.rs`, подключён через `FFONE_PERF_NPC_INTERACTION_RANGE=1`.
- Проверено: отдельный rustc harness включает **текущие** targeting/mod.rs и tests.rs с уже собранными workspace-зависимостями: **11 passed, 0 failed**. Новые регрессии проверяют 7.99/8.00/8.02/12 native units, вертикальный разрыв и фактическое создание/отсутствие TalkNpc при клике; отдельная регрессия — смена дистанции и нечисловые позиции. Журнал: `target/bug047-targeting.log`. Адресный git diff --check прошёл.
- Ограничения: `cargo test -p ffone-client --lib world_systems::targeting::tests -- --nocapture` не дошёл до тестов из-за 6 ошибок в параллельно изменяемых pc2pc и remote-player файлах (E0425/E0063/E0061/E0308). `cargo check -p ffone-client --bin ffone-client` после длительного ожидания успешно проверил библиотеку, затем остановился на чужой ошибке E0277 в `app/network_ingress/codec_handle_gameplay_frame.rs:195` (`&Res<TutorialMissionContent>` вместо каталога при apply_server_outcome). Diagnostics build более 20 минут ожидал общий build lock; остановлены только два своих ожидающих Cargo-процесса этой сборки. Обходная прямая сборка main с cached dependencies тоже не дала бинарник из-за несовместимости версий зависимостей и нового remote-player API; это не результат Cargo build. Full-client replay, его screenshot и серверное завершение задачи **не выполнены**, поэтому приёмка UI/round trip остаётся неподтверждённой.

Для адресной живой проверки после стабильной сборки: `FFONE_PERF_OUTPUT=target/bug047-full`, `FFONE_PERF_NPC_INTERACTION_RANGE=1`, запуск полного клиента. Replay проверяет дальний клик, близкое меню task 598 и закрытие устаревшего диалога после ухода от NPC; использует offline authority, не доказывает серверную выдачу предметов.
