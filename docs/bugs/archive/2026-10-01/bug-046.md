# Bug 46 — Журнал сохраняет выбранный активный квест

**Приоритет:** P2. **Статус:** исправлен в коде 2026-10-01; 3 регрессии прошли. Приёмка в полном клиенте не подтверждена из-за сторонних ошибок сборки executable. Снят из активной очереди как code-fixed.

## Объём и свидетельства

- [T022](../../source-list.md#t022) — При открытии журнала квестов активный квест сбрасывается на первый в категории.

## Причина и исправление

`close_journal` очищал просмотренный и отслеживаемый task ID, а `open_journal` безусловно назначал обоим первый активный квест. Обновление активного списка в `sync_world_mission_ui` заменяло данные без проверки, остался ли просмотренный квест в списке.

Модель хранит последний просмотренный Active quest ID отдельно от страниц Completed и NPC-награды. Закрытие сохраняет этот ID и отслеживаемую миссию. Открытие восстанавливает существующий просмотренный ID, затем существующий отслеживаемый ID, затем первый активный квест. Обновления сохраняют существующий выбор независимо от порядка строк; при исчезновении квеста выбирают существующий отслеживаемый, затем первый доступный; пустой список снимает просмотр. Подтверждённый TaskStop сохраняет свой прежний допустимый fallback и запоминает его для повторного открытия. Обновление активных квестов не меняет Completed-страницу и состояние её категорий. Сброс игровой сессии по-прежнему создаёт новую модель.

Изменены [model.rs](../../../../crates/ffone-client/src/ui/mission/model.rs), [journal_state.rs](../../../../crates/ffone-client/src/ui/mission/model/journal_state.rs), [world_mission.rs](../../../../crates/ffone-client/src/app/world_mission.rs), существующая проверка закрытия журнала и отдельный [integration-тест](../../../../crates/ffone-client/tests/mission_journal_selection.rs). Для последующей игровой проверки добавлен opt-in [offline replay](../../../../crates/ffone-client/src/app/performance_probe/journal_selection.rs), включаемый через `FFONE_PERF_JOURNAL_SELECTION=1` вместе с `FFONE_PERF_OUTPUT`; использует native task ID 451/2248.

## Проверки и ограничения

- `cargo test -p ffone-client --lib ui::mission::tests -- --nocapture` — тесты не запустились: сторонняя ошибка `P_FE2CL_PC_ENTER` в `world_systems/entity_lifecycle/tests/assets.rs` на момент сборки.
- `cargo build -p ffone-client --bin ffone-client` — библиотека с исправлением собрана; executable не собран: отсутствующий `world_pc_in_interaction_range` в PC2PC-пути, неверный тип каталога в сетевом обработчике, `ComputedNode.stack_index` в email probe и mutability в Nano HUD probe. Чужие изменения не исправлялись.
- Три integration-регрессии скомпилированы напрямую через `rustc --test` против свежего `libffone_client-f67341a256be7209.rlib` от 2026-10-01 21:01 и запущены как `target/bug-046-journal-selection-tests.exe --nocapture`: **3 passed, 0 failed**. Проверены не первый выбранный квест 501, повторное открытие, перестановка/обновление списка, исчезновение квеста, подтверждённый TaskStop и сохранение его fallback, пустой список, Completed-история, категории и NPC-награда.
- `git diff --check` для изменённого runtime и существующего unit-теста — прошёл.
- Полный клиент и offline replay не запускались: подходящий executable с этим исправлением собрать не удалось. Ручной ввод, визуальная проверка и серверное завершение миссии не подтверждены.

**T022:** code-fixed; игровая приёмка остаётся неподтверждённой. Порядок работы — [AGENTS.md](../../AGENTS.md).
