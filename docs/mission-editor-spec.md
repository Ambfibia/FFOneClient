# Техническое задание на редактор миссий FFOneClient

Дата: 03.10.2026. Статус: проект требований к реализации.

Переработать экран редактирования миссий в существующем нативном редакторе FFOneClient. Автор должен собирать миссию из этапов на схеме, изменять параметры на месте и создавать связанные тексты, предметы и NPC без ручного переноса идентификаторов между таблицами. Интерфейс должен объяснять смысл каждого доступного параметра и не позволять записывать неподдерживаемые значения.

ТЗ описывает будущее поведение. Оно не означает, что перечисленные функции уже реализованы или проверены в работающем клиенте. Числа в примерах макета условные; существующие идентификаторы сохраняются.

## Цель и границы работы

Основной пользователь — автор миссий, которому не требуется знать имена полей XDT или устройство таблиц. Основные задачи: найти миссию, понять последовательность событий, добавить этап, назначить цель и реплики, настроить награду, проверить результат.

В первую версию входят визуальная схема, редактирование связей, понятные типизированные поля, создание связанных записей на месте, единый поиск, проверенные значения по умолчанию, отмена действий и проверка данных. Это новый рабочий экран поверх существующих данных и механизмов редактора.

Не требуется вводить новый формат игровых миссий, универсальный язык сценариев, произвольные логические узлы или отдельную копию контента. Дополнительные ветвления доступны только в пределах возможностей FFOne / Retrobution 0104 и RustyFusion. Размещение нового NPC в мире остаётся отдельной операцией существующего редактора мира.

## Модель миссии и существующая основа

Фраза «каждая стадия — отдельный квест» описывает проблему представления. В текущих данных каждый этап является отдельной записью с собственным `m_iHTaskID`, а несколько этапов объединяются общим `m_iHMissionID`. В интерфейсе использовать термины «Миссия», «Этап» и «Цепочка миссий».

| Понятие | Представление для автора | Текущий контракт данных |
| --- | --- | --- |
| Миссия | Название и список этапов | Общий `m_iHMissionID` нескольких записей |
| Этап | Карточка на схеме с целью и исходами | Отдельный `m_iHTaskID` |
| Успешное завершение этапа | Стрелка «Успех» или подпись «Завершить миссию» | `m_iSUOutgoingTask`, содержащий ID следующего этапа; `0` означает отсутствие продолжения |
| Провал этапа | Стрелка «Провал» или подпись «Без следующего этапа» | `m_iFOutgoingTask`, содержащий ID этапа; `0` означает отсутствие перехода |
| Условие открытия миссии | Связь «После завершения миссии» | Элемент `m_iCSTReqMission`, содержащий ID миссии |
| Текст, предмет, NPC, награда | Именованная ссылка | ID сущности либо индекс строки согласно конкретному маршруту |

Текущий редактор уже содержит граф связей, создание миссии и этапа, автоматическое выделение ряда ID, подбор ссылок, группы параметров и Undo/Redo. Общий поиск уже проверяет содержимое записи, а подбор ссылок — имя и ID либо индекс. Требуется сделать эти возможности единообразными и дополнить поиск описаниями и текстами. Формулировку «сейчас поиск только по названию» считать наблюдением об удобстве интерфейса, а не основанием удалить существующий поиск по числам.

Сейчас общая форма создания берёт выбранную либо первую подходящую запись за шаблон. Для команды «Новая миссия» это поведение заменить проверенным нейтральным шаблоном. Копирование выбранной записи оставить отдельной явной командой «Дублировать».

## Компоновка основного экрана

Экран состоит из верхней панели действий и трёх изменяемых по ширине областей. Каталог занимает примерно 20%, схема — 50%, свойства — 30%; это исходное соотношение, а не жёсткие размеры. При уменьшении окна каталог можно свернуть, при этом выбранный этап и введённые данные сохраняются.

```text
Миссии    [Новая миссия]  [Отменить] [Повторить]  [Проверить] [Сохранить]

КАТАЛОГ                    СХЕМА                         СВОЙСТВА ЭТАПА
Поиск по имени, ID,         [Этапы] [Цепочка миссий]      Победить врагов
описанию…                                               (Этап ID: 4202)
                           [Начало: Разговор]
▾ Пример миссии                   (4201)                 ▸ Основное
  (Миссия ID: 700)                  │ Успех                Бой · Лёгкая
  • Разговор (4201)                 ▼                    ▸ Цель
  • Победить врагов (4202)  [Победить врагов] ← выбор       Враг (ID: 90) × 3
  • Вернуться (4203)               (4202)                 ▸ Диалоги
                                   │ Успех                Не заданы
                           [Вернуться (4203)]            ▸ Условия начала
                                   │                      Без ограничений
                           Завершить миссию             ▸ Награды
                                                         Нет
                           [+ Добавить этап]             ▸ При провале
                                                         Без перехода
                           [−] [100%] [+] [Вписать]     ▸ Дополнительно

Несохранённые изменения · Ошибок: 0 · Предупреждений: 1
```

В каталоге миссии группируются по настоящему ID миссии, одинаковые названия не объединяются. Этапы раскрываются под миссией. На схеме отображается ориентированный граф: разветвления и общие следующие этапы не дублируются ради формального дерева.

Переключатель «Этапы / Цепочка миссий» разделяет разные виды связей. В режиме этапов нельзя случайно записать ID миссии в переход, а в режиме цепочки — ID этапа в условие открытия. Переход к связанной миссии сохраняет масштаб, выделение и положение предыдущего вида; доступна команда «Назад».

Верхняя панель показывает состояние сохранения. Проверка сообщает конкретные проблемы и переводит к полю либо узлу. Сохранение не должно открывать обязательный обзор всех технических полей.

## Узлы и связи на схеме

Карточка этапа содержит короткое название, `(Этап ID: …)`, тип задачи, краткую цель и видимые выходы «Успех» и «Провал». ID миссии показывается в заголовке схемы и свойствах. Длинное название переносится; ID остаётся читаемым. Значки ошибок сопровождаются текстом.

ЛКМ выделяет узел и показывает его свойства. Перетаскивание заголовка перемещает узел; рамка выделяет несколько узлов, Shift добавляет к выделению. Перемещение пустого полотна выполняется средней кнопкой либо Space + ЛКМ. Колесо над полотном изменяет масштаб относительно курсора; колесо над каталогом, свойствами и списком выбора прокручивает соответствующую область.

Предусмотреть «Вписать схему», «К выбранному», «Масштаб 100%» и явную «Автораскладку». Новый узел размещается возле точки создания; остальные узлы не перестраиваются автоматически. Схема и пользовательская раскладка сохраняются отдельно от игровых параметров.

| Действие | Требуемое поведение |
| --- | --- |
| Протянуть стрелку из выхода к другому этапу | Создать соответствующий переход после проверки совместимости |
| Перетащить конец существующей стрелки | Переназначить переход одной отменяемой операцией; Esc возвращает прежнюю связь |
| Протянуть стрелку в пустое место | Предложить «Создать следующий этап»; после создания связать его с исходным выходом |
| Добавить узел между двумя этапами | Явная команда «Вставить этап в переход» меняет две связи одной операцией |
| Удалить стрелку | Удалить только связь, сохранить оба этапа; показать значение исхода без перехода |
| Удалить этап | Показать входящие и исходящие связи; заблокировать оставление битых ссылок, предложить явно удалить или переназначить их |
| Снять выделение или отменить создание | Сохранить данные существующих узлов и положение схемы |

У этапа имеется не более одного перехода успеха и одного перехода провала. Несколько входящих связей допустимы только при соблюдении игрового контракта. Подмена существующего выхода не должна незаметно удалять прежний маршрут: при перетягивании самой стрелки это явное переназначение, при создании второй стрелки интерфейс предлагает заменить имеющуюся.

Циклы условий открытия миссий запрещены. Циклы этапов проверяются отдельно: маршрут повторной попытки через провал нельзя запрещать только потому, что он образует цикл; новый цикл должен соответствовать поддерживаемому поведению. Неподтверждённые циклические конструкции недоступны для создания. Уже существующие циклы и отсутствующие цели отображаются с диагностикой и не исправляются автоматически.

Переход в другую миссию не появляется как обычный совместимый вариант. Существующую межмиссионную связь показывать явно; разрешение создавать такую связь требует подтверждённого контракта клиента и сервера.

Доступность первой стадии не выводится из координат узлов. Сейчас RustyFusion выбирает первый этап миссии по первой встретившейся записи группы. Перемещение узлов, сортировка каталога и автораскладка не меняют этот порядок. Маркер «Начало» отражает реальный порядок данных. Смена первого этапа — отдельная проверяемая команда; до реализации согласованного сохранения порядка она недоступна.

## Контекстные действия и клавиатура

ПКМ по пустому месту схемы открывает компактное меню с первой командой «Создать новый этап». ПКМ по узлу предлагает добавить следующий этап, дублировать, показать связи, скопировать ID и удалить. ПКМ по стрелке предлагает переназначить, вставить этап и удалить связь. Доступны только действия для текущего объекта.

ПКМ по полю ссылки предлагает открыть связанную запись, создать новую, скопировать ID либо индекс и посмотреть использования. Для текста доступны «Редактировать общий текст» и «Создать отдельную копию». Основные действия также доступны видимыми кнопками или меню действий, чтобы работа не зависела только от ПКМ.

| Комбинация | Действие |
| --- | --- |
| Ctrl+S | Проверить и сохранить документ |
| Ctrl+Z / Ctrl+Y | Отмена / повтор действия в текущем контексте |
| Ctrl+F | Перевести фокус в поиск каталога |
| Ctrl+D | Дублировать выбранный этап, если фокус вне текстового поля |
| Delete | Удалить выбранный узел или связь; внутри текста удалить символ |
| Enter | Применить однострочное значение или выбранный вариант |
| Ctrl+Enter | Применить многострочный текст или форму быстрого создания |
| Tab / Shift+Tab | Применить корректное значение и перейти к следующему / предыдущему полю |
| Esc | Закрыть подсказку, выбор или локальный черновик без изменения сохранённого значения |

Ctrl+A/C/X/V, выделение мышью, Shift+стрелки и работа с кириллицей сохраняются. Undo внутри текста сначала отменяет ввод в тексте; команда уровня документа не должна срабатывать одновременно.

## Правая панель и редактирование на месте

При первом открытии все разделы свойств свёрнуты, включая заполненные. Вне разделов остаются название выбранного объекта, его идентификаторы и состояние проверки. Панель не раскрывает десятки полей после выбора записи.

Заголовок каждого раздела содержит краткую сводку: «Награды — нет», «Цель — враг (ID: 90) × 3», «Условия начала — уровень от 5», «При провале — этап (ID: 4204)». Ошибка внутри свёрнутого раздела видна в заголовке. Клик по ошибке открывает только соответствующий раздел. Команда «Свернуть всё» доступна постоянно; раскрытие пользователем сохраняется в текущей сессии, но разделы не открываются сами из-за наличия данных.

Разделы: «Основное», «Цель», «Диалоги и тексты», «Условия начала», «При старте», «При успехе и награды», «При провале», «Дополнительно». Конкретные цели внутри раздела представлены понятными строками: «Победить: [Враг (ID)] × [Количество]», «Собрать: [Предмет (ID)] × [Количество]». Параллельные массивы ID и количеств редактируются как одна строка и сохраняются согласованно, без перестановки остальных слотов.

Тип этапа определяет рекомендуемые поля и обязательность. Не следует автоматически считать остальные условия несуществующими: текущие данные могут сочетать предметы, противников, NPC и таймер. Совместимые дополнительные условия доступны через «Добавить условие», а непустые существующие условия всегда отражаются в сводке. Смена типа не обнуляет скрытые значения: несовместимые данные перечисляются перед явным применением изменений.

Клик по значению сразу включает соответствующий элемент ввода в этой же строке. Отдельное окно с описанием не открывается. Для ссылок список выбора раскрывается у поля; поиск происходит в том же поле. Для числа используется числовой ввод, для перечисления — закрытый список, для логического значения — переключатель с подписью действия, для текста — строка или многострочный ввод по назначению.

Ошибка показывается возле поля. Некорректный ввод может временно оставаться в редакторе как черновик, но не попадает в модель и файл. Tab не уводит фокус с ошибочного поля; Esc восстанавливает предыдущее значение. Нельзя молча обрезать число, округлять его или подменять ближайшим допустимым кодом.

## Понятные названия и допустимые значения

Для каждого параметра, доступного автору, определить единое описание: понятное название RU/EN, назначение, тип, единицы измерения, допустимые значения либо диапазон, значение по умолчанию, смысл пустого значения и нуля, условия обязательности и зависимости. Для ссылки дополнительно определить таблицу назначения, вид идентификатора и возможность быстрого создания. Технический ключ и источник подтверждения доступны в расширенных сведениях.

Справочник должен использоваться одновременно при отображении, вводе, создании, проверке JSON/CSV и сохранении. Ограничения нельзя реализовывать только в выпадающем списке. Технический режим не разрешает обходить известные ограничения.

Для трёх полей с присланного скриншота установить следующие подписи и значения:

| Сейчас | Новая подпись | Значения в списке | Объяснение |
| --- | --- | --- | --- |
| Код сложности: `0` | Сложность | Лёгкая (0), Обычная (1), Сложная (2) | Метка сложности, отображаемая в журнале. Сама по себе не является настройкой здоровья врагов или наград |
| Код типа миссии: `3` | Категория миссии | Миссия наставника (1), Nano-миссия (2), Обычная миссия (3) | Определяет категорию миссии; категории связаны также с серверной организацией журнала. Выбор Nano не заменяет настройку выдачи Nano и прогрессии |
| Код типа задачи: `5` | Тип этапа | Разговор (1), Прибытие в точку (2), Использование предметов (3), Доставка (4), Победить врагов (5), Сопровождение / защита (6) | Определяет тип этапа. Условия и связанные объекты настраиваются отдельно |

Итак, пример со скриншота отображается как «Сложность: Лёгкая (0)», «Категория миссии: Обычная миссия (3)», «Тип этапа: Победить врагов (5)».

Названия типов этапов сверены с перечислением RustyFusion. Наличие значения в перечислении не доказывает работоспособность всех сценариев этого типа. Перед включением каждого варианта в создание проверить полный путь в клиенте и сервере. Если сценарий не поддержан, вариант виден с объяснением причины, но недоступен для выбора. «Сопровождение» и «Защита» могут стать отдельными пресетами одного кода `6`, если их параметры подтверждены.

Служебный `Unknown (0)` для категории и типа этапа не предлагать при создании. Он не является шаблоном пустой рабочей миссии. Числа вне разрешённых списков нельзя ввести через поле, вставку, импорт или JSON для новых и изменяемых значений.

Неизвестное значение в уже существующих данных показать как «Неподдерживаемое значение (код: …)», сохранив исходное число. Нельзя автоматически превращать его в ближайший известный тип. Неизменённые проблемные записи не блокируют сохранение несвязанных корректных правок; новая запись или изменение проблемного значения должны пройти актуальные ограничения.

Прочие обязательные правила:

- Вместо числовых флагов `0/1` использовать переключатель с глаголом, например «Выдавать повторно», только после подтверждения значения флага. Битовые маски с несколькими независимыми признаками не заменять одним переключателем.
- Для времени писать единицы и смысл отключения: «Лимит времени, сек»; для `m_iCSUCheckTimer` значение `0` означает отсутствие лимита. Не переносить эту трактовку на остальные таймеры без проверки.
- Для количеств указывать целочисленный диапазон, связанный с форматом и смыслом поля. Пустой слот цели и цель с нулевым количеством — разные состояния; сохранять их согласно схеме.
- Для процента, радиуса, уровня, награды и количества давать отдельные ограничения. Не вводить одно общее правило «все числа положительные».
- «Нет NPC», «Нет награды» и «Без перехода» показывать словами там, где отсутствие ссылки разрешено. Ноль не является универсальным отсутствующим значением: в индексных таблицах он может указывать на реальную строку.
- У полей с единственным допустимым значением показывать подписанное фиксированное значение и объяснение. У запрещённого по контексту варианта показывать причину недоступности.
- Для неподтверждённых технических полей прямо писать «Назначение пока не описано». Они доступны в «Дополнительно → Технические поля», сохраняют исходный тип и не получают выдуманных игровых объяснений. Покрытие понятными описаниями всех полей основного сценария обязательно до приёмки.

Краткая помощь показывается при наведении после 1,5 секунды неподвижного указателя. Она содержит назначение, эффект выбранного значения, единицы и ограничения. Расширенная справка открывается через ПКМ → «О параметре» или F1 при фокусе на поле. Обязательные ограничения и текущая ошибка доступны без наведения; подсказка не перекрывает редактируемую строку.

## Идентификаторы и поиск

В каждом элементе каталога, узле, результате поиска и выбранной ссылке показывать понятное имя и идентификатор в скобках. Формат должен различать домены: `Название (Миссия ID: 700)`, `Название (Этап ID: 4202)`, `Название (NPC ID: 90)`. У предмета дополнительно указывается категория, если одного ID недостаточно для однозначности.

У индексных текстовых записей отображать `Текст реплики (индекс: 312)`. Не называть индекс строки самостоятельным ID сущности и не вводить ради оформления второй идентификатор. Действие копирования явно называется «Скопировать ID» либо «Скопировать индекс».

Один и тот же поиск используется в каталоге и полях выбора. Он ищет без учёта регистра по имени, ID либо индексу, описанию, цели этапа и содержимому связанных пользовательских текстов. RU/EN доступны независимо от текущего языка интерфейса; у совпадения из другого языка показывается его язык. Ограничение типа сущности сохраняется: поле NPC не предлагает предметы из-за совпавшего числа.

Точный ID имеет приоритет, далее — начало названия, совпадение в названии, совпадение в описании или тексте. Числовой запрос не должен возвращать только точный ID, скрывая остальные совпадения. Результат содержит название, идентификатор и короткий фрагмент совпавшего описания. Поиск по нескольким словам учитывает все слова; отсутствие результатов сопровождается возможностью создать запись подходящего типа.

Дополнительные фильтры каталога: категория, тип этапа, NPC, наличие ошибок. Поиск внутри текущей схемы выделяет найденный узел и при выборе центрирует его, не меняя связи. Совпадения в свёрнутых разделах свойств доступны через поиск параметров.

## Быстрое создание связанных записей

Справа от каждого поля ссылки, где создание имеет смысл, находится кнопка `+` с доступной подписью «Создать …». Это относится к реплике, названию, описанию, NPC, предмету и награде. У обычной строки, не являющейся ссылкой на запись, кнопка создания ID не нужна.

Последовательность работы:

1. Автор нажимает `+` возле нужной ссылки.
2. В этой же панели раскрывается компактная встроенная форма. Миссия, положение схемы и редактируемое поле остаются на месте.
3. Редактор подставляет проверенные значения по умолчанию и показывает автоматически выделяемый ID или будущий индекс. Из введённого поискового текста можно взять начальное название; запись ещё не создана.
4. Автор заполняет видимые обязательные поля и нажимает «Создать и использовать».
5. Редактор проверяет запись, создаёт её и необходимые тексты, подставляет ссылку в исходный этап и возвращает фокус к нему. Все изменения составляют одну операцию Undo.

Отмена формы не добавляет строк, не меняет исходную ссылку и не оставляет пустой связанный объект. Нажатие `+` само по себе не записывает данные на диск.

Для текста сразу доступны RU и EN и понятная пометка незаполненного перевода. Новые локализационные ключи создаются согласованно для обеих локалей; placeholders сохраняются. Применяется существующая семантическая маршрутизация текстов, без второго каталога переводов.

Для NPC минимальная форма содержит имя и допустимый шаблон вида; для предмета — имя, категорию и обязательные свойства этой категории; для награды — поддерживаемые виды наград и количества. Универсальный произвольный «предмет» недопустим: квестовый предмет и предмет инвентаря создаются в правильном домене. Сложная настройка внешности открывается явной командой и возвращает автора в исходную миссию с сохранённым контекстом.

Создание типа NPC не размещает его в мире. После создания показывать статус размещения и действие «Открыть размещение NPC», если для игрового сценария нужен экземпляр. Миссия с недоступным в мире выдающим NPC не должна считаться проверенной в игре.

При работе с общим текстом показывать число использований. Обычное редактирование из миссии по умолчанию предлагает отдельную копию, если изменение затронет другие записи; «Изменить общий текст» остаётся явным действием. Копия сохраняет все поля текстовой записи и меняет только выбранную ссылку.

Идентификаторы выделяются в соответствующем домене с учётом диапазонов потребителя, занятых и резервных значений, незавершённых черновиков и внешних изменений файла. Нельзя без проверки использовать любое `max + 1`: ID миссии также ограничен серверным хранением флагов завершения, а часть других ID — более узкими числовыми типами. Перед применением и сохранением повторно проверяется уникальность. Для индексных таблиц строки добавляются без переиндексации существующих ссылок. Undo/Redo сохраняет идентичность созданной записи; конфликт ID выдаёт понятную ошибку, а не скрытое переназначение.

## Новая миссия и значения по умолчанию

Команда «Новая миссия» создаёт один этап и новую группу миссии по версионированному проверенному шаблону. Пользователь не обязан вручную задавать технические поля, чтобы открыть, сохранить и проверить заготовку. Название по умолчанию — «Новая миссия»; оно редактируется сразу.

| Параметр | Значение по умолчанию |
| --- | --- |
| ID миссии и этапа | Новые допустимые значения, выделенные автоматически |
| Название и текст цели | Собственные корректные текстовые записи с коротким понятным содержимым |
| Категория | Обычная миссия (3) |
| Сложность | Лёгкая (0) |
| Базовый тип этапа | Разговор (1) как основа простого шаблона; работоспособность шаблона обязательна к проверке |
| Дополнительные условия открытия | Отсутствуют в соответствии со схемой |
| Противники, предметные цели, сопровождение | Не заданы |
| Таймеры | Отключены допустимыми для конкретных полей значениями |
| Выдача предметов, наград, Nano | Отсутствует |
| Переход при успехе | Завершить миссию |
| Переход при провале | Без следующего этапа |
| Разделы свойств | Свёрнуты; показывают краткие сводки |

«Работает из коробки» означает два проверяемых результата: заготовка сохраняется и повторно открывается без исправления числовых кодов; в изолированном тестовом сценарии её можно запустить и завершить без боя, предметов и наград через поддерживаемый клиентом и сервером путь.

Нельзя обещать автоматическое игровое завершение лишь потому, что цели равны нулю. Событие запуска и завершения должно быть определено и проверено. Если миссия создаётся из контекста NPC, шаблон может использовать этого NPC для начала и сдачи. Если контекста нет, заготовка получает статус «Не назначен способ выдачи»; для проверки используется явно обозначенный тестовый запуск. Случайный NPC из таблицы не подставляется. Настройка способа появления миссии в игровом мире — содержательный выбор автора, а не исправление технических дефолтов.

До приёмки реализации зафиксировать точный набор полей шаблона и подтвердить прохождение в настоящем клиенте с RustyFusion. Если базовый тип `1` не обеспечивает нужный тестовый сценарий, скорректировать шаблон на основании потребителей, сохранив требование запуска и завершения без дополнительных целей. Не вводить для этого произвольный новый код типа задачи.

«Новый этап» сохраняет ID выбранной миссии и общее название, получает новый ID этапа и нейтральные параметры. «Дублировать этап» явно копирует настройки, выдаёт новый ID и по умолчанию не подключает копию к цепочке; исходящие переходы не копируются без отдельного выбора. Для общих текстов при дублировании показывается режим использования или копирования.

## Проверка и сохранение

Проверка выполняется при редактировании поля, изменении связей, создании записи и сохранении. Полная проверка по кнопке обходит текущую миссию и затронутые зависимости. Каждое сообщение содержит понятное объяснение, объект с идентификатором и переход к месту исправления.

Ошибки блокируют применение недопустимого изменения: неизвестный новый код, выход за диапазон, конфликт ID, новая битая ссылка, несовместимый тип цели, запрещённая связь, нарушение обязательного условия, неправильная длина массива или несогласованная пара ID/количество. Обнаружение ошибки не уничтожает ввод пользователя.

Предупреждения обозначают потенциальные авторские проблемы: нет способа выдачи миссии, этап недостижим от начала, созданный NPC не размещён, перевод не заполнен, путь повторной попытки требует проверки. Они не становятся безусловными ошибками структуры данных. В сводке отдельно различаются «Данные корректны», «Есть предупреждения» и «Проверено в игре».

Сохранять исходные ключи, неизвестные поля, явные ID, варианты и посторонние записи. Неизменённые старые проблемы должны оставаться видимыми, но не блокировать несвязанные изменения. Сворачивание, поиск, перемещение узлов и переключение вкладки не меняют игровые значения.

Создание связанной записи вместе с назначением ссылки, вставка этапа и удаление этапа с обработкой ссылок являются составными отменяемыми операциями. После ошибки операции исходный документ остаётся целым. Сохранение учитывает внешнее изменение файлов и не перезаписывает его молча.

Работа ведётся с `assets/game/data/tables/xdt.json` и существующими локализационными файлами. Положение узлов, масштаб и состояние панелей относятся к настройкам редактора с отдельной версионированной схемой и стабильными ключами миссии/этапа. Они не записываются в игровые поля. Новый параллельный каталог игрового контента не создаётся.

Запись нескольких файлов, например таблиц и RU/EN, не считается атомарной только потому, что каждый файл заменяется атомарно. Нужны предварительная проверка всего набора и восстановимый план сохранения: при частичной ошибке отображаются уже записанные и оставшиеся изменения, черновик сохраняется, повтор не создаёт дубликаты. Надпись «Сохранено» появляется только после успешной записи всего набора.

## Визуальный стиль и отзывчивость

Сохранить визуальную совместимость с нативным редактором: спокойные тёмные поверхности, читаемый контраст, утверждённые шрифты с кириллицей и английским. Выбранный объект выделяется акцентом, второстепенные сведения — менее контрастным текстом. Нельзя уменьшать шрифт до нечитаемого размера ради размещения всех полей.

Стрелки успеха и провала различаются подписью и рисунком линии, дополнительно — цветом. Ошибки и предупреждения различаются символом и текстом. Не использовать только цвет для передачи смысла. Кнопка `+` имеет заметную область нажатия и подпись при наведении; поля одного типа выглядят и работают одинаково.

Проверить экран при 1280×720 и 1920×1080, а также масштабировании интерфейса 100%, 125% и 150%. Длинные RU/EN названия не закрывают ID и кнопки. Каталог, граф и свойства прокручиваются независимо, всплывающий выбор остаётся внутри видимой области.

Целевые показатели для согласованной тестовой машины: реакция ввода и выбора до 100 мс, обновление результатов поиска до 200 мс на текущем каталоге, плавное перемещение схемы из 100 узлов без зависаний интерфейса. Проверять после прогрева данных; замеры и характеристики машины указать при приёмке. Большие каталоги и схемы используют виртуализацию или ограничение отображения, не теряя результатов поиска. Эти числа являются требованиями, а не измерением текущей реализации.

## Порядок реализации

1. Описать типизированную схему полей миссии, справочник значений и проверенный шаблон. Согласовать поведение пустой миссии и способ тестового запуска. Сохранить совместимость существующих данных.
2. Сделать компактные свойства: все разделы свёрнуты, сводки, ввод в строке, закрытые списки, помощь и единый поиск. Это первая полезная поставка даже до нового полотна.
3. Добавить встроенное создание текстов, предметов, NPC и наград с автоматическим назначением ссылки и составным Undo.
4. Доработать граф: перетаскивание узлов и стрелок, ПКМ, вставка этапа, сохранение раскладки, синхронизация схемы и свойств.
5. Пройти сценарии приёмки в реальном нативном редакторе и игровом клиенте с RustyFusion. Считать переработку завершённой после всех обязательных сценариев.

При реализации опираться на существующие владельцы: `crates/ffone-client/src/bin/editor/xdt/schema.rs` для схемы и описаний, `forms.rs` для создания, `relations.rs` для ссылок, `mission_graph.rs` для связей, `authoring.rs` и `presentation.rs` для свойств, `input.rs` и общего владельца ввода для взаимодействий. Новые части разделять по ответственности; не наращивать один универсальный файл интерфейса.

| № | Сценарий | Ожидаемый результат |

| 2 | Проверить поля со скриншота | Показаны «Лёгкая (0)», «Обычная миссия (3)», «Победить врагов (5)»; назначение доступно понятным языком |
| 3 | Ввести неподдерживаемый код через UI, вставку, JSON и CSV | Новое недопустимое значение не применяется; показана конкретная причина; обхода проверки нет |
| 4 | Открыть старую запись с неизвестным значением и изменить другую запись | Исходное значение не подменяется; несвязанная корректная правка сохраняется |

| 18 | Удалить этап, на который есть ссылки | Входящие связи видны; нельзя сохранить новые битые ссылки; связанные тексты и NPC не удаляются автоматически |
| 19 | Сменить тип этапа с заполненными дополнительными условиями | Условия не исчезают молча; несовместимости объяснены; отмена возвращает исходное состояние |

Автоматические проверки должны покрывать семантику кодов, ограничения, идентичность и ссылки, составные операции, сохранение и неизменность посторонних данных. UI-приёмка выполняется взаимодействиями в работающем редакторе, а игровые сценарии — в работающем клиенте с RustyFusion. Скриншот или тест только модели данных не заменяет эти проверки.

Числовые значения и ограничения уточняются по действующим потребителям данных, а не по внешнему виду скриншота.
