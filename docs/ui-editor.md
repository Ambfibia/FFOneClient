# FFOne UI Editor

`FFOne UI Editor` — отдельное desktop-приложение внутри репозитория
`FFOneClient`. Оно не запускает игру и не встраивает редакторские системы в
игровой executable.

Запуск из корня `FFOneClient`:

```powershell
cargo ui-editor
```

Также можно запустить `run-ui-editor.cmd`. После первой сборки напрямую
доступен `target/debug/ffone-ui-editor.exe`.

## UserEquip

Редактируемый документ находится здесь:

```text
assets/game/ui/en/user-equip/user-equip.ffui.json
```

Игра загружает этот JSON через Bevy AssetServer. Править Rust-константы не
нужно. Если документ отсутствует, не загрузился или у элемента снят флажок
`Apply in game`, клиент использует доказанный исходный Rect из кода.

Стартовая раскладка рассчитана на контрольный кадр `1264x681` и содержит
отдельные пространства координат для панели персонажа, инвентаря, полосы
экипировки и popup предмета. На холсте они автоматически переводятся в общие
экранные координаты, а в JSON сохраняются локальные координаты, которые нужны
игре.

Редактор рисует UI из тех же native PNG и replacement-font `jeffe.otf`,
которые использует клиент. Nine-slice-панели собираются по runtime border, а
картинки, которые появляются только во время игры (3D-персонаж, Nano, предметы
и skill icons), отмечены полупрозрачным checker. Checker означает динамический
источник, а не отсутствующий или угаданный asset.

## Отдельные UI-формы

Редактор не смешивает независимые окна на одном холсте. Форма выбирается из
списка `Форма UI`:

- `Инвентарь` — основная книга инвентаря, вкладки, TAROS и общие кнопки;
- `Инвентарь — все 50 ячеек` — полный scroll-content без обрезки viewport;
- `Карточка — экипировать` — полная карточка характеристик на фоне
  `equip-popup.png`;
- `Карточка — снять` — независимая карточка надетого предмета на фоне
  `unequip-popup.png`;
- `Карточка — использовать` — компактный consumable-диалог с кнопкой `USE`;
- `Карточка — сундук` — отдельный компактный диалог с кнопкой `OPEN`;
- `Статус персонажа` — нижний блок имени, уровня, здоровья, Fusion Matter и
  Guide размером `498x115`;
- `Экипировка` — вертикальная полоса из девяти ячеек, Boosts и Potions;
- `Персонаж и Nano-статус` — полная левая панель, три Nano status-окна и
  runtime-область 3D-персонажа;
- `Nano — все 64 ячейки` — полная gallery, включая строки ниже viewport;
- `Карточка Nano` — фон, три skill-блока, requirements и все labels;
- `Помощь инвентаря` — самостоятельное help-окно;
- `Item Mode — взаимное расположение` — общий холст панелей для проверки
  стыков и относительного выравнивания.

Список слева, выбор мышью, фильтр групп и hit-зоны содержат только элементы
активной формы. Переключение формы автоматически подгоняет её холст в рабочую
область. Кнопка `Вписать форму` повторяет подгонку после ручного изменения масштаба.
Контрольный GPU-кадр больше не является составной частью UI и по умолчанию
скрыт. Ползунок `Эталонный скриншот` накладывает его только для сравнения.
Переключатели `UI`, `Границы` и `Имена объектов` независимо управляют
реальными слоями, редакторскими Rect и служебными подписями.

Варианты карточки имеют разные ID геометрии: `item_popup_*`,
`item_unequip_*`, `item_use_*` и `item_chest_*`. Поэтому изменение кнопки или
текста одного типа предмета не меняет остальные карточки. Runtime выбирает
вариант по endpoint и `item_type`: надетый предмет, обычная экипировка,
используемый предмет (`7`) или сундук (`9`).

Управление:

- щелчок по рамке или строке слева выбирает элемент;
- перетаскивание рамки перемещает элемент;
- жёлтая рамка и точка под курсором показывают, какой Rect получит нажатие;
- белый маркер в правом нижнем углу изменяет размер;
- прокрутка колёсиком и полосами прокрутки двигает холст, но не перехватывает
  перетаскивание левой кнопкой;
- если Rect'ы перекрываются, уже выбранный элемент получает приоритет; при
  первом выборе редактор предпочитает наименьшую подходящую область;
- стрелки двигают выбранный элемент на один пиксель;
- `Shift + стрелка` двигает на десять пикселей;
- `Ctrl+S` сохраняет JSON;
- `Ctrl+Z`, `Ctrl+Shift+Z` и `Ctrl+Y` управляют историей;
- `Привязка` и `Сетка` задают шаг привязки;
- точные координаты формы и размер доступны в инспекторе справа; локальные
  runtime-координаты спрятаны в секции `Технические координаты`;
- секция `Внешний вид в редакторе` показывает точный asset, label, font,
  режим Stretch/Nine-slice и Z-порядок;
- список `Относительно` выбирает опорный объект; кнопки `L/C↔/R` и
  `T/C↕/B` совмещают края или центры, а `W/H` копируют ширину или высоту;
- те же операции можно применить ко всей группе выбранного объекта;
- `Распределить по X/Y` делает равные промежутки между тремя и более
  незаблокированными объектами одной группы;
- кнопки со стрелками в инспекторе двигают элемент с шагом 1, 5 или 10 px;
- `Вернуть исходный Rect` возвращает конкретный элемент к исходной
  геометрии Retrobution;
- `Применять в игре` позволяет временно отключить override без удаления записи.

Контрольный PNG нужен только для опционального сравнения и не является
runtime-зависимостью. Его можно заменить параметром:

```powershell
cargo ui-editor -- --background target/ui-parity/another-frame.png
```

Другой layout-документ открывается так:

```powershell
cargo ui-editor -- --layout assets/game/ui/en/user-equip/user-equip.ffui.json
```
