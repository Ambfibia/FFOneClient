# Расстановка NPC: координаты и угол

## Как снять позицию в FFOneClient

1. Войдите персонажем с GM-доступом (`accountLevel <= 50`).
2. Введите в чат `/viewloc`. Написание `/viweloc` тоже поддерживается.
3. Встаньте на место будущего NPC, дождитесь приземления и поверните **персонажа** в нужную сторону. При необходимости немного пройдите вперёд: свободный поворот камеры сам по себе не задаёт направление персонажа.
4. Запишите карту, три координаты `XYZ` и `iAngle`. Панель обновляется раз в 0,2 секунды.
5. Повторная команда скрывает панель.

Пример показаний: `Карта=0 XYZ=54728,65509,-10469 iAngle=90° (персонаж)`.

| Показание | Поле серверного JSON | Значение |
| --- | --- | --- |
| Карта / map | `iMapNum` | Номер карты; `0` — основной мир |
| Первое число XYZ | `iX` | Первая горизонтальная координата |
| Второе число XYZ | `iY` | Вторая горизонтальная координата |
| Третье число XYZ | `iZ` | Высота |
| iAngle | `iAngle` | Целый угол в градусах, направление персонажа |

Переносите числа **без пересчёта**: XYZ уже в серверных единицах, угол уже в формате OpenFusion. Отрицательные координаты и углы допустимы. Не меняйте знак угла и не прибавляйте 180°. Символ `°` в JSON не записывается. `/goto` принимает другие единицы (в 100 раз крупнее), поэтому эти XYZ нельзя передавать ему напрямую.

## Где хранится расстановка

Для сетевой игры позиции задаёт сервер **OpenFusion**. Основной файл в соседнем репозитории: [`OpenFusion/tdata/NPCs.json`](../../OpenFusion/tdata/NPCs.json). В нём объект `NPCs` содержит отдельные размещения:

```json
{
    "NPCs": {
        "0": {
            "iNPCType": 2379,
            "iX": 54728,
            "iY": 65509,
            "iZ": -10469,
            "iAngle": 90,
            "iMapNum": 0
        }
    }
}
```

Это пример структуры, а не файл для полной замены. Для переноса существующего NPC отредактируйте только его `iX`, `iY`, `iZ`, `iAngle` и при необходимости `iMapNum`. Сохраните ключ размещения и `iNPCType`.

- Ключ `"0"` — идентификатор размещения в файле. В текущем загрузчике серверный ID равен этому числу **плюс 1**. Например, для NPC ID `1` ищите ключ `"0"`. `/viewid` показывает серверные ID и типы ближайших загруженных NPC (список ограничен 20 записями).
- `iNPCType` — тип NPC, а не ID размещения: несколько размещений могут иметь одинаковый тип. Для нового размещения нужен свободный числовой ключ и существующий подходящий тип NPC.
- Если `iMapNum` отсутствует, загрузчик использует основной мир (`0`).
- Модели и таблицы типов в `FFOneClient/assets/game` не задают серверные позиции сетевых NPC.

## Как убедиться, что редактируется активный файл

Проверьте конфигурацию **запущенного сервера** (`config.ini`, секция `[shard]`):

| Настройка | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `tdatadir` | `tdata/` | Каталог данных относительно рабочей папки сервера |
| `npcdata` | `NPCs.json` | Основная расстановка NPC |
| `mobdata` | `mobs.json` | Расстановка монстров |
| `gruntwork` | `gruntwork.json` | Сохранённые дополнительные размещения и переопределения |
| `patchdir` | `tdata/patch/` | Каталог патчей |
| `enabledpatches` | См. активную конфигурацию | Подключённые папки патчей, разделённые пробелами |

Путь к NPC-файлу строится как `tdatadir` + `npcdata`. При запуске из другой папки или с другой конфигурацией это может быть другая копия данных. Патчи загружаются поверх базовых JSON: проверьте соответствующие `NPCs.json` в подключённых папках.

После основных таблиц применяется `gruntwork.json`:

- `rotations`: записи `iNPCID` / `iAngle` переопределяют угол существующего NPC; здесь `iNPCID` — **серверный** ID.
- `instances`: записи `iNPCID` / `iMapNum` переопределяют карту существующего NPC.
- `mobs`: дополнительные размещения, в том числе мирных NPC, с полями `iNPCType`, `iX`, `iY`, `iZ`, `iAngle`, `iMapNum`.
- `groups`: группы монстров; координаты лидера и смещения последователей.

Если NPC добавлен через `gruntwork`, редактируйте его там, а не создавайте дубликат в `NPCs.json`. У NPC с маршрутом движения начальная позиция может меняться после появления: проверьте `paths.json` и `paths` в `gruntwork.json`.

## Применение и проверка

1. Сохраните исходную версию редактируемого файла в системе контроля версий или резервной копии.
2. Остановите сервер перед ручной правкой, особенно `gruntwork.json`: сервер умеет записывать этот файл и может перезаписать ручные изменения.
3. Измените нужную запись. Сохраните валидный JSON: числа без кавычек, правильные запятые, никаких комментариев.
4. Запустите сервер заново и переподключите клиент: таблицы размещений читаются при старте сервера.
5. Проверьте нужную карту, положение ног NPC, направление его лица и отсутствие дубликата. Для моделей с необычной геометрией проверьте высоту визуально.

Изменение файлов локального OpenFusion влияет только на сервер, который их загружает. Для другого сервера изменения нужно передать его владельцу и применить в его активных данных.
