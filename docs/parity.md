# Parity: scope and acceptance

Observable compatibility must name its reference build and server configuration.
Current integration targets RustyFusion/0104; OpenFusion observations are historical
reference. Implementation, source-backed contract and live parity are different claims.

Match packet bytes/order, explicit IDs, authority and semantic state. For rendering/audio/
timing, declare viewport/backend/tolerances and inspect comparable output. A native GPU
frame is not a Unity golden; static IL is not runtime reachability.

For the requested slice only, retain source/config identity, focused evidence, native
consumer/test, relevant success/failure/malformed/timeout cases, comparison and unresolved
limits. Classify `unclassified`, `not started`, `partial`, `reference matched` or `regressed`.
Compilation, generated output and a historical passed test do not imply present acceptance.

[Historical backlog](parity-backlog.md) preserves issue IDs, not an instruction to run a
whole-client audit. Use the affected [UI contract](native-ui.md), [wire inventory](protocol-0104-inventory.md)
or asset contract before treating a dated missing-feature report as current.

Release blockers include ignored required packets, guessed assets, hidden source/runtime
dependencies, mismatched client/server state after reconnect, lost localization/voice
identity, nondeterministic conversion, nonrepeatable auth/logout/cold-start, and exceeded
measured performance/queue budgets. Broad journeys and release audits are separate tasks,
not prerequisites to each local fix.
